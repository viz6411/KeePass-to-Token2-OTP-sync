# Техническое задание: Утилита синхронизации TOTP-ключей между KeePassXC и Token2 PIN+ R3.3

## 1. Общее описание и цели проекта
Настоящее техническое задание описывает архитектуру, требования безопасности, логику работы и сценарии использования кроссплатформенной консольной утилиты для синхронизации TOTP-ключей из базы данных KeePassXC (`.kdbx`) на аппаратные токены безопасности **Token2 PIN+ R3.3**.

### Ключевые требования
* **Безопасность (Zero-Disk-Footprint):** Незашифрованный экспорт базы данных, сырые TOTP-секреты и временные файлы не должны записываться на физический накопитель. Все операции парсинга выполняются исключительно в оперативной памяти (RAM).
* **Идентификация по URI:** Сопоставление сервисов и учётных записей выполняется строго на основе параметров внутри строки `otpauth://` (`issuer` и `account`/`label`), а не по произвольным заголовкам записей в KeePassXC.
* **Аппаратная цель:** Token2 PIN+ R3.3 (ёмкость до 300 TOTP-профилей, алгоритмы `SHA1`/`SHA256`, длина кода `6`/`8` цифр, интервал `30`/`60` секунд, защита PIN-кодом).
* **Удобство запуска:** Запуск в один клик / одной командой через готовый лаунчер, который автоматически открывает терминал в нужном окружении и переходит в интерактивный режим.
* **Кроссплатформенность:** Основная целевая ОС — **Windows 10/11**; дополнительная поддержка — **Linux** и **macOS**.

## 2. Архитектура решения

### 2.1 Технологический стек
* **Язык и среда выполнения:** Python 3.11+
* **Взаимодействие с KeePassXC (основной способ):** Официальный консольный инструмент `keepassxc-cli`, вызываемый через `subprocess` с перенаправлением потоков `stdin`/`stdout` (потоковый экспорт XML напрямую в оперативную память без создания файла на диске).
* **Взаимодействие с KeePassXC (резервный/альтернативный способ):** Библиотека `pykeepass` для прямого чтения и расшифровки `.kdbx` в RAM (с поддержкой паролей, ключевых файлов и аппаратного Challenge-Response).
* **Взаимодействие с Token2:** Официальная CLI-утилита от Token2 (`otp-cli.exe` / `token2-otp-cli`), вызываемая через модуль `subprocess`.
* **Консольный интерфейс (TUI/CLI):** Библиотека `rich` (форматированные таблицы расхождений, статусные панели) + интерактивные промпты (`questionary` или стандартный ввод) для выбора режима синхронизации.
* **Упаковка и запуск:** Скрипты-обёртки для запуска в один клик (`.bat` + ярлык для Windows, `.desktop`/`.sh` для Linux, `.command` для macOS).

### 2.2 Схема потоков данных
```text
+-------------------+     (1) Расшифровка в RAM (pipe)     +------------------------+
|  База KeePassXC   | -----------------------------------> |   KeePassXC Reader     |
|     (.kdbx)       |   (Мастер-пароль / Ключ / YubiKey)   | (XML/KDBX RAM-парсер)  |
+-------------------+                                      +------------------------+
                                                                       |
                                                                       v (2) Извлечение otpauth://
+-------------------+     (3) Вызов CLI-утилиты            +------------------------+
| Token2 PIN+ R3.3  | <----------------------------------> |  Модуль сверки (Diff)  |
| (USB HID / CCID)  |     (list / add / delete через CLI)  | (Нормализация и сверка)|
+-------------------+                                      +------------------------+
                                                                       |
                                                                       v (4) Интерактивный выбор
                                                           +------------------------+
                                                           |    Консольный UI       |
                                                           | Отчёт и выбор режима   |
                                                           +------------------------+
```

## 3. Требования информационной безопасности

1. **Отсутствие следов на диске (Zero-Disk-Footprint):**
   * При вызове `keepassxc-cli export` запрещено указывать путь к выходному файлу. Весь поток перехватывается из `stdout` в буфер `io.BytesIO` в оперативной памяти.
   * Запрещено использование временных файлов (`tempfile`, `%TEMP%`, `/tmp`) для хранения дампа базы или промежуточных списков ключей.
2. **Очистка оперативной памяти:**
   * Секретные ключи (`secret`), мастер-пароль и PIN-код хранятся в изменяемых буферах `bytearray` и принудительно затираются нулями (`b[i] = 0`) сразу после завершения сеанса или при возникновении исключения / прерывания `Ctrl+C`.
   * При запуске устанавливается переменная окружения `PYTHONDONTWRITEBYTECODE=1` для предотвращения записи `.pyc`-файлов.
3. **Защита от утечки через список процессов:**
   * Мастер-пароль от базы KeePassXC и PIN-код токена запрашиваются через скрытый ввод (`getpass.getpass()`) и передаются только через `stdin` (никогда не передаются в открытом виде в аргументах командной строки).
4. **Исключение корзины и архива:**
   * Записи, находящиеся в группе `Recycle Bin` (Корзина) или в пользовательских исключённых группах, игнорируются при парсинге, чтобы удалённые ключи считались отсутствующими в базе.

## 4. Модуль работы с KeePassXC

### 4.1 Поддерживаемые методы разблокировки базы
Утилита поддерживает все стандартные способы аутентификации KeePassXC:
1. **Мастер-пароль:** Скрытый запрос в консоли и передача в `stdin` процесса `keepassxc-cli`.
2. **Ключевой файл (`.keyx` / `.key`):** Передача пути через флаг `--key-file`.
3. **Аппаратный ключ (Challenge-Response, например YubiKey):** Поддержка через флаг `--yubikey <slot>:<serial>`.
4. **Комбинированные режимы:** Любое сочетание мастер-пароля, ключевого файла и аппаратного ключа.

### 4.2 Извлечение и нормализация `otpauth://`
Из каждой активной записи базы извлекается атрибут `otp` (стандартное поле KeePassXC для хранения TOTP).

Пример строки:
`otpauth://totp/GitHub:octocat?secret=JBSWY3DPEHPK3PXP&issuer=GitHub&algorithm=SHA1&digits=6&period=30`

**Правила парсинга (`urllib.parse`):**
* Проверяется схема `otpauth` и тип `totp` (`hotp` пропускаются).
* Из пути (`path`) после URL-декодирования извлекается связка `Issuer:Account` (если двоеточие отсутствует, используется только `Account`).
* Из query-параметров извлекаются:
  * `secret` — приводится к верхнему регистру, удаляются пробелы.
  * `issuer` — имеет приоритет над префиксом в `path`.
  * `algorithm` — по умолчанию `SHA1` (проверяется совместимость с Token2: `SHA1`, `SHA256`).
  * `digits` — по умолчанию `6` (проверяется совместимость: `6` или `8`).
  * `period` — по умолчанию `30` (проверяется совместимость: `30` или `60`).
* **Ключ идентификации записи:** Каноническая пара `(normalize(issuer), normalize(account))`, где `normalize()` удаляет крайние пробелы и переводит строку в нижний регистр.

## 5. Модуль работы с Token2 PIN+ R3.3

### 5.1 Адаптер CLI (`Token2CLIAdapter`)
Взаимодействие с физическим токеном инкапсулировано в отдельный класс-адаптер поверх официальной CLI-утилиты Token2:
1. **Обнаружение устройства и PIN-аутентификация:**
   * Проверка наличия подключённого токена. Если подключено сразу два токена (например, основной и резервный), утилита выводит их список и предлагает выбрать целевой токен (или синхронизировать оба по очереди).
   * Если на токене включена защита PIN-кодом, утилита запрашивает PIN через `getpass.getpass()`.
2. **Чтение списка профилей (`list`):**
   * Вызов команды просмотра записей на токене, парсинг `stdout` для получения индекса слота, `issuer` и `account`.
   * *Примечание по проверке актуальности секрета:* Поскольку прошивка Token2 PIN+ R3.3 из соображений безопасности блокирует обратное чтение сырого Base32-секрета с устройства, для точного определения изменённых ключей применяется гибридный механизм:
     * Если CLI токена возвращает контрольный хэш или проверочный код — используется прямое сравнение.
     * Дополнительно в самой зашифрованной базе KeePassXC (в служебном поле или отдельной скрытой записи) хранится SHA-256 слепок (fingerprint) параметров `(issuer, account, secret, algorithm, digits, period)` последней синхронизации для каждого серийного номера токена. Это сохраняет принцип *Zero-Disk-Footprint* и гарантирует 100% точное обнаружение ротации ключа.
3. **Добавление профиля (`add`):**
   * Вызов CLI-команды добавления с параметрами `issuer`, `account`, `secret`, `digits`, `period`, `algorithm`.
4. **Удаление профиля (`delete`):**
   * Удаление записи по точному номеру слота / идентификатору профиля.
5. **Обновление профиля (`update`):**
   * Выполняется последовательно: удаление старого слота (`delete`) $\rightarrow$ запись обновлённого профиля (`add`).

## 6. Логика сверки (Diff Engine) и сценарии работы

### 6.1 Категории расхождений
После сравнения данных из KeePassXC и Token2 формируются 4 списка:
1. **Новые (`to_add`):** Есть в KeePassXC, отсутствуют на токене.
2. **Обновлённые (`to_update`):** Присутствуют и в базе, и на токене, но изменился секретный ключ или параметры генерации (`period`, `digits`, `algorithm`).
3. **Устаревшие (`to_delete`):** Присутствуют на токене, но отсутствуют в базе KeePassXC (удалены или перемещены в корзину).
4. **Несовместимые (`skipped`):** Записи в KeePassXC с параметрами, не поддерживаемыми Token2 PIN+ R3.3 (например, алгоритм `SHA512`).

Перед применением изменений выполняется **проверка ёмкости**:
$$\text{Итоговое число слотов} = N_{\text{текущих}} - N_{\text{удаляемых}} + N_{\text{добавляемых}} \le 300$$

### 6.2 Интерактивный отчёт и 3 режима синхронизации
В консоли выводится сводка:
* Занято слотов на токене: `X / 300`
* Новых ключей для добавления: `N`
* Изменённых ключей для обновления: `M`
* Устаревших ключей на токене: `K`

Если расхождений нет, утилита сообщает об актуальности базы и завершает работу. При наличии изменений пользователю предлагается выбрать одно из действий:

1. **Только добавить новые (`Add Only`)**
   * Записывает на токен только отсутствующие ключи (`to_add`).
   * Изменённые и устаревшие записи на токене не затрагиваются.
2. **Добавить новые и обновить изменённые (`Add & Update`)**
   * Записывает новые ключи (`to_add`) и перезаписывает обновлённые (`to_update`).
   * Устаревшие записи на токене не удаляются.
3. **Полная синхронизация (`Full Sync: Add, Update & Delete`)**
   * Записывает новые ключи (`to_add`), перезаписывает обновлённые (`to_update`) и удаляет с токена устаревшие записи (`to_delete`), которых больше нет в KeePassXC.
   * Перед удалением запрашивается дополнительное подтверждение `[y/N]`.
4. **Выход (`Cancel`)**
   * Завершение работы без внесения изменений на токен.

## 7. Обработка ошибок и граничных случаев

* **Неверный мастер-пароль / отсутствие ключевого файла:** Перехват ошибки `keepassxc-cli`, понятное сообщение пользователю, до 3 попыток повторного ввода.
* **Защита от блокировки PIN-кода токена:** При неверном PIN-коде утилита **немедленно** прекращает работу без повторных автоматических попыток, чтобы не исчерпать счётчик попыток PIN на аппаратном ключе.
* **Потеря связи с токеном во время записи:** При отключении USB во время пакетной операции скрипт останавливается, выводит точный прогресс (`Выполнено X из Y`) и очищает буферы памяти. Повторный запуск безопасен благодаря идемпотентности сверки.
* **Дубликаты записей в KeePassXC:** Если в базе найдены две активные записи с одинаковой парой `(issuer, account)`, утилита предупреждает пользователя и просит разрешить конфликт до начала записи на токен.

## 8. Конфигурация и удобный запуск (One-Click)

### 8.1 Файл конфигурации (`config.toml`)
Хранится в пользовательской директории (`%APPDATA%\t2-kpxc-sync\config.toml` на Windows; `~/.config/t2-kpxc-sync/config.toml` на Linux/macOS) и содержит только несекретные пути:

```toml
[keepassxc]
database_path = "C:/Users/User/Documents/Passwords.kdbx"
keyfile_path = ""                 # Опционально: путь к ключевому файлу
yubikey_slot = ""                 # Опционально: слот Challenge-Response (например, "2")
cli_binary = "keepassxc-cli"
excluded_groups = ["Recycle Bin", "Archive"]

[token2]
cli_binary = "otp-cli"
```

### 8.2 Запуск в один клик по платформам
* **Windows 10/11 (основная платформа):**
  * Создаётся скрипт-лаунчер `Sync-Token2.bat` и ярлык для рабочего стола / меню «Пуск»:
    ```bat
    @echo off
    title KeePassXC -> Token2 PIN+ R3.3 Sync
    set PYTHONDONTWRITEBYTECODE=1
    cd /d "%~dp0"
    python -m t2_kpxc_sync
    pause
    ```
  * При необходимости доступа к HID-интерфейсу токена в свойствах ярлыка устанавливается флаг «Запуск от имени администратора».
* **Linux:**
  * Настраивается правило `udev` (`/etc/udev/rules.d/70-token2.rules`) для доступа к USB-устройству без `root` и ярлык приложения `t2-kpxc-sync.desktop` с параметром `Terminal=true`.
* **macOS:**
  * Исполняемый файл `Sync-Token2.command`, открывающий стандартный `Terminal.app` при двойном клике в Finder.
